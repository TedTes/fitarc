# Back artwork and highlight regions

The app's back muscle map uses `assets/images/muscle-map/athlete-back-v7.png`
unchanged at its native **1084 × 1451** dimensions. Front artwork remains v4 at
896 × 1200. Rendering, zoom and hit testing use the dimensions for the selected view.

## Editable source and preview

- `assets/images/muscle-map/athlete-back-v7-regions.svg`: authoritative, editable
  paths in native v7 pixels. Each path has a stable `id`, `data-muscle`, label and
  review color. Mirrored regions are subpaths of the same muscle selection.
- `scripts/muscle-map/references/back-colored-guide.jpeg`: the user's labeled
  guide, retained unchanged for comparison.
- `scripts/muscle-map/review/back-v7.html`: open in a browser to inspect all
  regions or one region, adjust opacity, hide the artwork and zoom the upper body.
- `src/screens/runtime/backMuscleContours.ts`: generated app geometry, traced by
  `trace_back_v7.py`. Do not edit this file directly; regenerate it after editing the SVG.

The colored guide is 896 × 1199 and contains shading, label lines, changed
clothing and inconsistent anatomical labels. It was used as a visual guide for
manual tracing and registration against #7, not as a pixel-exact segmentation.
The new SVG contains no label-line artifacts. The athlete bitmap was not repainted.

## Interpretation and limits

These are approximate surface highlight regions, not a clinically validated
anatomy atlas. Strong definition in the generated artwork does not guarantee
anatomical correctness. Registration keeps the chosen boundaries fixed to the
artwork at every display size; it does not establish anatomical accuracy.

- Trapezius has upper, middle and lower display regions. Rhomboids are not
  exposed as a separate surface patch beneath it.
- Infraspinatus, teres minor and teres major have independent selectable regions.
- The lower-back region uses two areas alongside the spine; there is no colored
  stripe directly over the spinal midline.
- Glutes are a subdued **location beneath clothing**, not visible muscle borders.
- Hamstrings use outer and inner surface regions; deeper heads are not invented.
- Medial and lateral gastrocnemius are separate. Soleus follows visible side
  portions; the central Achilles region is left unhighlighted.
- Forearms are included in the editable reference SVG but omitted from runtime
  masks because the current training model has no forearm group.
- The app still computes training status at muscle-group level. More selectable
  shapes do not imply separately measured stimulus or progress for each part.

Anatomical references used when interpreting the guide:

- https://www.kenhub.com/en/library/anatomy/infraspinatus-muscle
- https://www.kenhub.com/en/library/anatomy/rhomboid-muscles
- https://www.kenhub.com/en/library/anatomy/erector-spinae-muscles
- https://www.kenhub.com/en/library/anatomy/gastrocnemius-muscle

## Tracing from the artwork

The SVG regions are guides, not the final shapes. `scripts/muscle-map/trace_back_v7.py`
traces each region from the v7 image itself: shapes are clipped to the body outline (skin
and shorts are far less saturated than the orange glow), borders between neighbouring
muscles snap to the real grooves (a watershed over dark seams and edge strength, seeded by
each guide's core), and every edge may move at most a few pixels from its guide. Whole-group
highlights (all of back, all hamstrings) are traced as one merged outline, so a group shows a
single border rather than one per part. `review/back-v7-traced.png` shows the result.

## Regenerate and validate

```sh
python3 scripts/muscle-map/build_back_regions.py          # review page only
.venv/bin/python scripts/muscle-map/trace_back_v7.py      # app geometry (numpy, scipy, scikit-image, opencv)
python3 scripts/muscle-map/build_back_regions.py --check
npm run muscle-map:check
npm run typecheck
```

The SVG guide was recovered from the paths embedded in the saved review HTML after its source file was removed. The review check verifies those paths are unchanged; the existing traced runtime geometry is preserved.

The review-page compiler uses only Python's standard library. No image-generation call is
needed. The front segmentation generator preserves the back import and its own
native dimensions. The targeting check inspects the actual image imports and
checks the corresponding overlay sizes, region identities and catalog coverage.

Visual and interaction checks were performed on the actual `MuscleMap` component
in a local React Native Web harness at 390 and 640 pixels wide: group/part taps,
individual calf selection, keyboard activation, zoom and front/back switching.
This is browser verification, not an iOS-device test.
